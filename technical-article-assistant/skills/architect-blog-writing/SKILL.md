# Architect Blog Writing

Produce technical articles that read like they were written by someone who has designed systems, shipped them, and supported them in production.

## Goals

- Make the article strategically useful to senior engineers, architects, and technical leaders.
- Clarify why the problem matters, not just how a tool works.
- Explain trade-offs, constraints, risks, and operational consequences.
- Prefer evidence, runnable examples, diagrams, and reviewable decisions.

## Required Sections

1. Problem framing
2. Why common advice is insufficient
3. Architecture options and trade-offs
4. Recommended design and reasoning
5. Implementation details and example structure
6. Operational concerns: security, observability, scale, delivery, cost
7. Anti-patterns and failure modes
8. Final guidance for adoption

## Writing Rules

- Write with strong opinions that are explained, not asserted.
- Avoid shallow top-10 listicles and generic introductions.
- Use precise engineering language.
- Name the boundary between product concerns, platform concerns, and code concerns.
- If the topic touches AI, include evaluation, guardrails, traceability, and failure recovery.
- If the topic touches .NET or DevOps, include deployment and operational implications.
